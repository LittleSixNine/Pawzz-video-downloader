# Pawzz-video-downloader

**把趴趴爪喂食器里的日常录像，留一份在自己手里。**

有时想把宠物的一段吃饭记录留下来，有时只是想在设备里的旧录像被覆盖之前，存好一份原片。Pawzz Video 做的就是这件事：把设备仍保存着的原始 MP4 导出到电脑或 NAS，保留日期目录和原文件名，不录屏，也不转码。

你可以偶尔打开它，导出一次；也可以把它放在 NAS 上，按计划持续归档。也可以让熟悉的 Agent 帮你准备配置、检查环境，再执行一次导出。三种方式使用相同的原片校验流程。

> **目前适用于趴趴爪喂食器 Pro，尚未在其他设备上验证。** 请不要将现有结果视为其他型号也能使用。

> **当前为实验性工具。** 依赖特定设备固件的维护通道与厂商 MQTT 服务。本版通过本地回归验证；设备连接、回调、会话有效性及群晖原片导出需按教程进行实机验收。厂商接口可能变化，也不承诺兼容其他型号与固件。

- [Docker / 群晖教程](docs/deployment.md)：Docker 通用设置、群晖 Container Manager、证书、权限、更新与回退。

## 选一种适合你的用法

| | 电脑按需导出 | Docker 持续归档 | Agent + Skill |
|---|---|---|---|
| 适合什么时候 | 手动保存一批录像 | 定期存进 NAS | 用自然语言交代导出任务 |
| 怎么打开 | Mac 双击 `start.command` | Linux / 群晖运行 Compose | 给 Agent 安装 `pawzz-export` Skill |
| 在哪里操作 | 这台电脑的浏览器 | 局域网中的浏览器 | 支持本地执行的 Agent 对话 |
| 录像存到哪 | 默认“影片 / Pawzz Video”，网页可改 | 安装时指定的宿主机文件夹 | 你指定的本地文件夹 |
| 什么时候运行 | 点击开始后只执行一轮 | 手动一轮，或开启自动归档 | 本地检查后，按已授权范围执行一轮 |
| 使用期间 | 电脑唤醒、启动窗口开启 | NAS / 容器持续运行 | Agent 所在电脑可访问设备局域网 |

**电脑本地部署比 Docker / NAS 更简单：安装 Python 后双击启动文件即可打开本机页面，不需要 Docker 或 NAS HTTPS 证书，也无需手工准备登录 JSON。**

管理台默认浅色，也可以切换深色。首页看当前任务和可用空间，任务页回看结果，设备页集中设置连接与导出范围。电脑版隐藏了定时归档选项，避免把一次导出误设成后台服务。

## 开始前，准备好这几样

- 自己拥有或获得使用授权的**趴趴爪喂食器 Pro**，以及设备序列号、设备的局域网 IPv4。其他设备尚未验证。
- 官方 App 使用的手机号，以及接收短信验证码的手机。网页可直接登录；已有 `session.json` 的用户仍可使用高级导入 / 挂载方式。
- 同一可信局域网中的电脑或 NAS，设备能够连接其回调端口；保存端也能访问厂商 MQTT TLS 服务。
- 足够的磁盘空间。程序会尽量保留 **5 GiB** 余量，不会为了腾空间自动删除旧录像。

它只能读取设备上仍存在的文件，不能找回已经被覆盖的录像。首次使用时建议只导出一个已完成的原片，确认结果正常，再扩大范围。不要让电脑与 NAS 同时控制同一设备或使用同一 MQTT 账号导出。

## 直接登录，不必手工准备 JSON

在“设备与存储”里输入官方 App 使用的手机号，点击发送验证码，再填写手机收到的验证码。请求由你自己的电脑或 NAS 通过 HTTPS 发给厂商，本项目没有接收这些信息的中转服务；程序不主动把手机号或短信验证码写入文件、日志或浏览器持久存储。不要把它们发给 Agent 或贴进 Issue。

登录成功只是准备好账号，**不会自动开始导出或开启维护读取**。仍需确认设备配置、维护许可，再点击开始。

- **电脑按需导出**：登录凭据只在本次服务内存中使用。任务成功、失败或停止后继续保留，退出账号或关闭服务时清除。关闭网页本身不会退出账号或停止任务。
- **Docker / NAS**：默认也临时使用，容器停止后丢失，重启需重新登录并开启自动归档。只有主动勾选 **“在此 NAS 加密保存登录状态，用于持续归档”**，才会保存持续归档所需凭据。未勾选时，启用自动归档的当前服务可持续使用内存中的凭据；同一服务生命周期内保留，退出账号或关闭容器时清除。
- **Agent**：使用 `--web-login` 打开本机页面，由你亲自输入手机号和验证码、点击开始。Agent 只收到等待 / 任务结果，不需要接触账号凭据。

**加密前的 JSON 内容只有 `user_id`（账号标识）和 `token`（登录凭据），不保存手机号和短信验证码。**

选择保存后，程序使用 [Fernet 认证加密](https://cryptography.io/en/latest/fernet/)，实际写入的是私有配置目录下的 `login/session.enc`，不是明文 JSON。随机解密密钥放在独立的 `PAWZZ_KEY_DIR` 目录（容器内 `/keys/session.key`），不写进源码、镜像、网页或环境变量值。首次保存时自动生成，已有密钥不会被覆盖。凭据与密钥文件均以 `600` 权限创建，其专用目录为 `700`。

**它能防止凭据文件单独泄露后被直接读取；不能防止凭据文件与密钥同时泄露，也不能抵挡已取得 NAS 管理员权限的访问。** 不要将两者打包分享或放进同一份不受保护的备份。密钥丢失后无法恢复旧凭据，可退出后重新短信登录。保存选项默认关闭；加密保存失败时保留临时登录，并说明具体失败步骤；重启后临时登录失效，修复权限后可直接再次保存，不会降级写入明文。

网页提供“退出账号并清除本程序保存的凭据”，会停止任务、关闭自动归档并移除上述文件。已有外部会话文件与备份不会被删除，厂商端会话不会因此撤销。旧版本留下的 `session.json` 也需自行管理；程序不悄悄删除用户原件。短信登录或退出后不会回退使用旧外部文件。

`session.json` 是高级兼容入口：`user_id` 是厂商账号标识，不能直接假定为手机号；`token` 是登录后取得的凭据，不是密码或短信验证码。它也不同于网页管理密钥 `admin-token`。会话过期时重新登录，不自动发送短信或续期。

**NAS 远程输入登录信息必须使用 HTTPS。** 普通 HTTP 页面会禁止短信登录；本机电脑版的 `127.0.0.1` 可直接使用。证书配置见 [部署指南](docs/deployment.md#4-准备-https)。程序不承诺绝对无痕：系统交换内存、崩溃转储、浏览器扩展、NAS 备份及厂商的数据处理不在它的控制范围内。完整说明见 [安全与隐私](SECURITY.md)。

## 可选：无损修复缩略图

“设备与存储 → 导出范围”提供“开启无损修复缩略图”，默认关闭，电脑和 Docker / NAS 均可使用。开启后先下载并校验原片，再用 FFmpeg 无损重新封装，纠正设备 MP4 尺寸头导致的绿色缩略图；视频、音频不重新编码，并核对各流 SHA-256。原片及原片校验记录保持原样，修复版另存于保存目录的 `repaired/日期/原文件名.mp4`，拥有独立校验记录。再次运行会补修已校验原片，并跳过已校验修复版。修复失败会停止本轮并保留原片，修复版约需额外一份录像空间。

Docker 镜像通过 Alpine 软件包安装 FFmpeg；新的 macOS 完整发行包自带 Apple 芯片和 Intel 两种 FFmpeg，无需另装 Homebrew。程序优先使用对应架构的内置版本，缺失或不可用时检查系统 FFmpeg；设置与诊断页显示来源、版本及可用状态。开启修复前和启动任务前都会检查，避免下载完成后才发现缺少工具。关闭修复时，原片导出不依赖 FFmpeg。

macOS 内置版仅支持本项目需要的 MP4 无损封装和流校验，不提供通用转码功能；完整源码、LGPL 许可与重建脚本随包提供。源码仓库不跟踪生成的二进制与源码压缩包，直接克隆源码的开发者需运行 `tools/build_macos_ffmpeg.sh` 构建，或安装系统 FFmpeg。Agent 设置 JSON 使用 `"repair_video": true`，直接运行导出器使用 `PAWZZ_REPAIR_VIDEO=yes`。

## 在 Mac 上导出

1. 安装 [Python 3.10 或更新版本](https://www.python.org/downloads/macos/)，下载并解压项目。
2. 双击根目录的 **`start.command`**。首次启动会在项目之外建立运行环境，并下载所需 Python 依赖；之后会自动打开本地网页。
3. 进入“设备与存储”，用手机号和验证码临时登录，确认原片保存位置。填写设备 IP、序列号和**这台电脑的局域网 IP**，阅读并勾选维护读取许可，保存设置。
4. 回到首页，点击 **“开始导出”**。已校验完成的段数和最终结果会显示在页面中。

如果下载的启动文件不能双击执行，在项目目录打开终端，运行 `bash start.command` 即可。不要为此关闭系统安全设置。

默认网页地址为 `http://127.0.0.1:8080`。如果端口已被其他程序占用，会选择空闲端口并打开正确地址。启动时的自动连接链接只可用一次、60 秒内有效；刷新网页后，用管理密码重新连接；首次安装默认 `admin`，已有安装继续使用原密码，可在设置中即时修改。

关闭网页不会停止正在执行的任务。完成后，在启动窗口按 **Control-C** 退出；任务进行中退出也会请求停止，已校验的原片会保留。更多说明见 [电脑版使用指南](docs/desktop.md)。

## 在 Docker / 群晖上归档

需要可运行 Linux 容器的 Docker 与 Compose。先阅读 [部署指南](docs/deployment.md)，准备仓库外的配置、独立密钥、会话 / 证书和录像目录，将专用账号 UID/GID 填入 `.env` 的 `PAWZZ_UID`、`PAWZZ_GID`，匹配配置和密钥目录所有者，然后在项目根目录执行：

```sh
cp .env.example .env
# 编辑 .env，填写专用账号 UID/GID、四个绝对路径和 HTTPS 设置。
docker compose up -d --build
```

打开 `http://NAS局域网IP:18080`，首次安装用默认管理密码 `admin` 连接，已有安装继续使用原密码。启用 HTTPS 后可在“访问设置”中修改管理密码，立即生效，不限制长度或大小写（不能为空）。若端口已占用，修改 `.env` 的 `PAWZZ_WEB_PORT`。此 HTTP 页面可查看状态、管理已有会话；直接短信登录前需按部署指南启用 HTTPS。已有 `session.json` 仍可放在只读挂载的会话目录中。

在“设置 → 归档设置”保存范围与间隔后，到概览右上角点击“开启自动归档”；如需单次验收，可点击旁边的下拉箭头，选择“只运行一次”。自动归档开启后立即执行一次，以后默认在每轮结束 **24 小时** 后再运行，也可以选 1、3、6、12 小时或 2、3 天。失败后每 10 分钟重试，最多追加 3 次；仍失败则等待下个常规周期。“停止当前任务”只停止本轮，保留自动计划；“暂停自动归档”只取消后续调度，本轮继续执行。退出趴趴爪账号仍会停止本轮并关闭计划。

## 让 Agent 帮你导出

项目附带 [pawzz-export Skill](skills/pawzz-export/SKILL.md)，适合 Codex 等支持本地 Skill、文件访问和命令执行的 Agent。它负责找对入口、准备私有配置、先做本地检查，再按你的许可导出一轮；短信登录会打开本机网页，整个过程不需要 Docker。

Agent 必须运行在能访问设备局域网的 Mac / Linux 上。只在云端运行、没有本地执行能力的聊天助手不能直接连接你的设备。手机号和验证码由你在本机网页中输入，Agent 不代填、不截取这些输入。“安装”本身不会开始导出。现有 Skill 的默认流程使用会话文件；需要短信登录时，使用下方明确指定 `--web-login` 的任务文案。

**复制下面这段给 Agent；如本机已有项目副本，可把第一行改成本地路径：**

```text
项目地址：https://github.com/LittleSixNine/Pawzz-video-downloader

请帮我安装这个项目，以及其中 skills/pawzz-export 的 Skill。
先阅读 README、LICENSE 和 SKILL.md；复用已有环境，缺少时建立独立的 Python 3.10+ 环境并安装项目依赖。
把 pawzz-export 安装到你实际使用的 Skill 目录，已有同名文件先比较，不直接覆盖，也不要改我的全局 Agent 规则。
安装后验证 src/agent_export.py --help 能运行，告诉我项目位置、Skill 位置，以及之后需要的设备信息与保存路径。
这次只安装，不连接设备、不导出录像、不启动 Docker，也不查找或上传我的账号凭据。
```

安装后，可以这样交代任务（方括号内容换成自己的路径）：

```text
使用 pawzz-export，帮我把设备仍保留的录像导出到 [保存目录]。
设备配置在 [设置 JSON 路径]。本轮使用 src/agent_export.py 的 --web-login 入口，由我在本机网页临时登录并点击开始；不要读取、代填或截图手机号、验证码和账号凭据。
先做本地检查，不在聊天中显示会话内容。这是我自己的设备，本轮允许使用维护读取通道导出；不修改设备配置，不删除已有录像，不开启定时任务。
```

还没有设置文件时，直接让 Agent 协助准备即可；它需要设备 IP、序列号、电脑局域网 IP 和导出范围。已有会话也可提供本地文件路径，别把 token 粘进对话。Agent 使用的命令行入口会返回简短 JSON，实际运行仍经过同一套 MD5 校验和空间保护。`check` 成功仅代表本地条件通过，不代表设备连通性已经验证。`--web-login` 会先返回等待用户操作的 JSON，再返回最终结果，同时保留网页任务历史；高级 `--session` 入口只返回结果，不写网页历史。三种方式都能识别已校验的原片。

```sh
.venv/bin/python src/agent_export.py check --settings /path/to/settings.json --web-login --output /path/to/videos
.venv/bin/python src/agent_export.py run --settings /path/to/settings.json --web-login --output /path/to/videos --allow-maintenance
```

`check --web-login` 只检查本地条件，不打开网页；实际 `run` 打开本机页面，等待登录以及任务结束后均保留页面服务，退出服务时才关闭。账号输入只在用户页面进行，Agent 不应操作或截图登录表单。

## 设置与任务控制

账号、设备与存储、归档选项分组管理。设备与归档分别保存，彼此不会覆盖未保存草稿；管理密码位于“访问设置”。保存配置不会启动任务，自动计划已开启时普通设备保存保留原调度，修改间隔则从保存时按新间隔安排下一轮。

NAS 概览主按钮未开启时为红色“开启自动归档”，开启后恢复主题色并显示“自动归档运行中”；再次点击暂停计划。概览右上角主按钮用于开启／暂停自动归档，旁边下拉箭头中的“只运行一次”按已保存设置执行一轮，不改变自动计划；电脑版仍直接显示手动导出。“开启自动归档”立即安排第一轮，已有任务运行时则在本轮结束后按间隔继续。再次开启不会重复安排。“暂停自动归档”只阻止后续任务，“停止当前任务”只停止本轮，保留自动计划；后续仍按常规间隔执行，不因主动停止立即重试。

任务运行期间可编辑草稿，结束后才能保存；切换分组不会丢失草稿，刷新或关闭网页会丢失未保存修改。首次配置允许先保存归档选项，补全设备设置与维护许可后才可运行。IP 与 MAC 至少填一项，NAS 回调 IP 始终必填。指定原片与连接端口在高级设置中。

## 原片怎样才算保存好了

Linux/NAS 的“设备连接”支持选填设备 MAC（如 `02:11:22:33:44:55`）。IP 与 MAC 可同时填写，优先使用设备 IP；首次回调超时后才按 MAC 重新查找并尝试新地址。不填设备 IP 时每轮直接按 MAC 查找，适合路由器重启后设备地址变化的情况。NAS 回调 IP 仍需固定且正确。喂食器与 NAS 必须位于同一局域网，子网最多 1024 个地址（如 `/24`）；macOS 电脑版继续填写设备 IP。旧设置无需修改，MAC 留空仍按原有设备 IP 工作。

自动识别会向 NAS 所在子网的其他地址各发送一个 UDP 探测包，再读取系统邻居表，通常增加约 13 秒准备时间。找不到设备或地址不唯一时停止本轮并记录具体原因，不在 MAC 查找失败后继续尝试旧 IP。Docker 更新需要重新构建镜像以安装 `iproute2`；已有配置、凭据、原片与校验记录继续保留。MAC 用于局域网地址发现，不代替账号、序列号及回传校验。

设备读取前、读取后和本地文件的 **MD5 三方一致**，程序才会把临时文件作为正式 MP4 保存，并写下配套的 `.mp4.json` 校验记录。

- 已有且校验通过的原片会跳过；没有有效校验记录的同名文件不会被覆盖。
- 逐个传输，跳过最近约 10 分钟内或仍在写入的录像，留到下次处理。
- 目录或单段读取超时会追加重试最多 3 次，每次间隔 5 秒，重试期间保留控制连接且不关闭维护通道。每次使用新的接收端，已有校验通过的原片跳过；校验失败、空间不足、账号拒绝和主动停止不重试。整轮结束或主动停止时尝试关闭维护通道。
- 空间不足时暂停，保留已经保存好的原片。电脑版释放空间后手动重试；自动归档每 10 分钟检查并尝试恢复。
- 网页模式会保留最近 100 轮任务记录。服务意外中断时，未完成任务标为“结果未确认”，不会被当作成功。

“已配置”“会话可读取”只是本地准备检查，不代表设备在线或登录仍有效。页面目前显示运行状态和已校验新增段数，**没有单文件百分比、速度或预计剩余时间**。

## 任务日志与排障

任务历史继续保留最近 100 轮摘要。新版另在私有配置目录的 `logs/` 保存结构化详细日志，按北京时间分日，例如 `2026-10-28.jsonl`；单文件最多 2 MiB，同日最多 3 卷（`.jsonl.2`、`.jsonl.1`、`.jsonl`，从旧到新），超过容量保留最新记录。写入任务事件时清理 14 天以前的日期文件，最多约 84 MiB，不创建日志数据库。

任务页点“查看日志”可定位到该任务的结束日期；也可在诊断页选择日期和任务。页面不随状态刷新加载详细日志，点击后只显示最近 200 条；“下载所选日志”下载该日期、该任务的全部保留记录，留空任务筛选则下载当天全部任务。跨午夜任务按实际事件时间分日，需切换日期查看。旧任务不补生成详细日志，超龄或超容量部分不可恢复。

事件记录任务编号、重试关联编号、执行阶段、耗时、固定拒绝原因、异常类型、系统错误码及 HTTP 状态。账号凭据、验证码、设备地址、序列号、回传密钥、原片路径、原始异常消息与原始进程输出不写入详细日志。查看和下载沿用管理密码认证。日志目录 `700`、文件 `600`；日志写入失败会在页面提示，导出与原片保护流程继续执行。

详细日志覆盖网页管理服务发起的 NAS/电脑版导出（含 Agent 的网页入口）。高级 `--session` 单次 Agent 入口不写网页任务日志，仍返回固定结果 JSON。

## 可选 NAS 统一通知

配置目录存在专用 `notify.json` 时启用通知适配器；未配置时保留原导出行为。通知在独立线程发送，任务结果与调度心跳先存入 `notify-outbox/`，不发送账号会话、设备序列号、文件路径或原始日志。现有诊断、设备发现、重试与空间保护保留。

接入步骤见独立 `nas-notify` 项目的 `deploy/README.md`（NAS 部署使用随包说明）。当前仅本地与 Linux 离线验证，尚未在真实 NAS 或真实渠道验收。

通知失败阈值、重复间隔、首次提醒类型与恢复通知在本项目“设置 → 通知”中调整，保存于配置目录的 `notify-policy.json`；对后续结果生效，不修改下载程序原有重试次数。通知中心只显示此策略，独立设置每个项目的渠道和提醒方式。升级至 NAS Notify 0.2 时保留原发件箱，并按配套文档备份、更新两端后确认项目路由。

NAS Notify 0.3 的“通知”设置可查看待传数量、最近成功、当前错误与最近故障，并可单独刷新状态而保留未保存策略。发送端仅上报白名单状态，凭据错误与连接失败分别记录；相同故障不重复刷日志，恢复后再次故障会重新记录。请先升级通知中心，再更新发送端，保留原发件箱。
