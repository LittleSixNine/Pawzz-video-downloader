# Pawzz Video：Agent 导出

复用 Pawzz Video 项目的 `src/agent_export.py`，不自行拼 MQTT、维护命令或下载脚本。项目通过设备维护通道读取原始 MP4，依赖厂商 MQTT TLS 控制服务和局域网回调。保留原文件名、日期目录及 `.mp4.json` 校验记录。

## 安装与定位

先确定用户提供的 Pawzz Video 仓库地址或现有项目路径，读取其中 README 与 LICENSE。没有地址且本地没有项目时询问，不猜测下载源。Skill 可以独立复制安装，但运行时仍需要完整项目；不要把源码相对位置假定为 Skill 的父目录。

在用户选定的目录获取代码，使用项目现有 Python 3.10+ 环境，或建立隔离环境后安装 `requirements.txt`。当前 Agent 入口支持 Mac / Linux；Windows 尚未适配。安装本 Skill 时，完整复制此含 LICENSE 的 `pawzz-export` 目录到该 Agent 的 Skill 目录；Codex 通常是 `~/.codex/skills/`，其他 Agent 使用其自己的约定，不修改全局行为文件。已有同名 Skill 先比较，未经用户确认不覆盖。

仅安装请求以安装和 `python src/agent_export.py --help` 验证为止，**不会因此获得连接设备或导出录像的授权**。不自动启动 Docker、关闭其他任务或配置定时导出。

## 准备本轮任务

按用户请求确定保存目录、导出起始日或单个原片范围，以及设备 IPv4、序列号、当前电脑可被设备访问的局域网 IPv4。没有日期要求时可按设备现存全部日期；不要假设设备或账号归属。保留已提供的授权，不重复询问同一事项。

会话必须由用户在自己的设备上准备，包含 `user_id` 与 `token`。优先接收本地文件路径，不请用户把 token 发到聊天中。项目目前不提供会话获取、账号登录或续期功能；缺失时如实告知，不访问无关凭据存储，也不从日志、历史会话或其他应用中找秘密。

在仓库外保存设备设置 JSON，权限仅当前用户可读写。可复用用户已有设置；不要悄悄修改正在运行的电脑 / NAS 设置。最小字段如下，值须替换为用户实际设备信息：

```json
{
  "device_ip": "192.168.1.50",
  "callback_ip": "192.168.1.10",
  "serial": "YOUR_DEVICE_SERIAL",
  "start_date": ""
}
```

可选 `callback_port` 默认 10003、`source` 只接受 `/data_fs/record/日期/原片.mp4` 格式。开始日期为 `YYYY-MM-DD`，留空扫描现存全部日期。整个过程不打印或上传会话内容，不把真实设置、录像或运行日志写进代码仓库。

## 检查与执行

从项目根目录、使用项目 Python 环境运行。下面路径都是变量占位，执行时使用已确定的真实路径并正确引用，不把 token 放进参数或环境变量：

```sh
.venv/bin/python src/agent_export.py check --settings "$SETTINGS_FILE" --session "$SESSION_FILE" --output "$OUTPUT_DIR"
```

`check` 只验证设置、会话格式、目录与空间，不创建目录，不向设备发命令。返回 `ready` **不代表设备在线、会话有效或回调可达**。不要将它描述成传输验收通过。

实际 `run` 前须有用户对本轮导出及使用固件维护读取通道的明确许可。若尚未获得，简要说明它使用高权限读取通道，确认后再执行；已经明确许可的同一范围内不重复确认。不要扩大导出日期 / 目录范围。确认没有电脑或 NAS 任务同时控制同一设备 / MQTT 账号，不擅自停止其他服务。程序只锁住同一配置目录，不能替代跨目录或跨机器的任务协调。

```sh
.venv/bin/python src/agent_export.py run --settings "$SETTINGS_FILE" --session "$SESSION_FILE" --output "$OUTPUT_DIR" --allow-maintenance
```

只运行一轮，没有后台调度或自动重试。导出期间保持电脑唤醒与局域网连接；可能跳过最近约 10 分钟内或仍在写入的录像。状态仅输出不含凭据的 JSON；执行期间没有百分比，不编造进度。用户要求停止时发送正常终止信号并等待清理，避免先强杀；断网或掉电时远端通道关闭仍可能失败。

出口状态：0 本地检查通过或导出成功（看 JSON 的 status）；1 导出失败；2 设置 / 授权 / 实例冲突；3 空间不足；130 已停止。失败后先报告固定错误类别，不循环试探设备。修正原因后仅在既有授权范围内重试。已有且校验通过的原片会跳过，不覆盖未知文件，不自动删除任何已保存录像。

完成后报告实际新增段数、保存目录、是否完成校验以及未验证或失败事项。CLI 的成功计数来自共用导出核心，意味着这些新增原片已通过三方 MD5；0 新增不代表设备没有录像。中途失败、暂停或停止时 `new_files` 为 null：已有文件可能成功保存，但本轮总新增数未确认，应如实报告未知，不写成 0。不要把 Mac 结果当成 NAS 验收，也不要自动上传、发布录像或变更设备配置。
