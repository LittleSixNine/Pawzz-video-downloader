# 部署、诊断与验收

以下命令均从项目根目录执行；[返回项目介绍](../README.md)。

## 适用范围

本页针对 Linux / NAS 持续归档。支持在自己的 HTTPS 管理页短信登录；已有 `session.json` 可继续只读挂载。真实短信登录与群晖联调仍待验收。

本工具只面向使用者自有或获授权设备与可信局域网。固件维护处理器会将服务器地址拼入高权限 shell；程序使用固定命令模板并校验地址与路径。不要扩大到固件、录像或设备配置写入，不要向公网开放回调端口。

网页使用随机管理密钥认证，写接口限制同源请求，密钥不放在网址或浏览器持久存储中。HTTP 本身不加密；推荐按下文启用本程序 HTTPS；短信登录强制要求 HTTPS，VPN 内的普通 HTTP 也不会放行该接口。网页不挂载 Docker socket，不提供任意命令执行或任意宿主机文件读取。

## Linux / 群晖

1. 将公开代码放入独立项目目录。不要把个人资料或完整工作区作为构建上下文。
2. 创建配置、会话 / 证书、原片及独立密钥四个宿主机目录。例如 `/volume1/pawzz-private/config`、`/volume1/pawzz-private/secrets` 、`/volume1/pawzz-videos` 与 `/volume1/pawzz-keys`。按自己的实际存储卷调整。隐私目录仅限管理者访问，并检查 DSM ACL；不能只依赖 `chmod`。
3. 把 `.env.example` 复制为 `.env`，填入上述四个绝对目录。宿主机挂载目录及网页端口属于安装设置，不能在网页里改变。
4. 启动 `docker compose up -d --build`（Container Manager 也可创建 Project）。默认常驻网页服务，即使没有会话也能打开设置页。
5. 在配置目录读取 `admin-token`，于 `http://NAS局域网IP:18080` 输入密钥。不要将密钥、`.env` 或会话贴进公开日志。可停止服务后删除该密钥文件再启动，以生成新密钥。
6. 按下节启用 HTTPS，在“设备与存储”用手机号和验证码登录。默认临时使用；需要重启后自动归档时才勾选“在此 NAS 加密保存登录状态”。已有会话也可在只读会话目录放置 `session.json`，只包含 `user_id` 和 `token`。真实有效性在导出时确认。
7. 网页填写设备序列号、设备 IP、NAS 回调 IP 与回调端口（默认 10003），先指定一段已完成原片，明确允许维护读取，保持自动归档关闭，保存后运行一次。

设备与回调地址必须是 RFC1918 私网 IPv4。NAS 应允许设备访问回调 TCP 端口、允许 NAS 连接厂商 MQTT TLS 服务；网页端口与回调端口不得相同。Linux Compose 使用 host 网络，回调地址填 NAS 可被设备访问的地址，不填容器虚拟地址。多网口时选择与设备互通的接口。不要同时运行多个容器控制同一设备或共用同一 MQTT 账号。

`PAWZZ_WEB_PORT` 在 Compose 中默认 18080；可在 `.env` 改端口。`PAWZZ_CONFIG_DIR`、`PAWZZ_SECRETS_DIR`、`PAWZZ_OUTPUT_DIR`、`PAWZZ_KEY_DIR` 对应宿主机挂载目录。容器内分别为 `/config`、`/run/secrets`、`/videos`、`/keys`。密钥目录必须独立于配置目录，不得公开共享。配置与密钥文件以 600 权限创建。

未指定环境变量时，Compose 将数据放在代码目录旁的 `../pawzz-data/`；正式安装建议填写 `.env` 使用明确的绝对路径。升级时保留原来的目录与端口，不要因为更换代码而改挂载路径。已有安装若沿用 8080，在 `.env` 中明确写入即可。

## 为 NAS 启用 HTTPS 登录

1. 准备浏览器信任、包含实际访问域名的证书完整链 `fullchain.pem` 与私钥 `privkey.pem`，放在 `.env` 中的宿主机 `PAWZZ_SECRETS_DIR` 目录。它已只读挂载，无需把证书复制进项目或镜像。保护好私钥和 DSM ACL；不要把证书私钥发到聊天。
2. 在 `.env` 填入容器内路径：

   ```dotenv
   PAWZZ_TLS_CERT=/run/secrets/fullchain.pem
   PAWZZ_TLS_KEY=/run/secrets/privkey.pem
   ```

3. 重新执行 `docker compose up -d`，打开 `https://证书对应的局域网域名:18080`（如自定义端口则替换）。浏览器需正常验证证书，不可忽略证书警告。此时同一端口只接受 HTTPS，旧 HTTP 地址失效。
4. 连接管理台后在设备页登录。勾选保存时把仅含 `user_id` 与 `token` 的 JSON 加密为 `/config/login/session.enc`，不写手机号或验证码。首次保存自动在独立 `/keys/session.key` 生成密钥；缺少目录或写权限时拒绝保存，不降级明文。凭据文件与密钥应分别保护，不能一起分享或进入同一份不受保护的备份。密钥在 NAS 上由 `PAWZZ_KEY_DIR` 指定，检查其 DSM ACL。

配置证书失败时服务拒绝启动，不会退回 HTTP。当前使用本程序直接提供 TLS；仅在 DSM 反向代理上终止 HTTPS、再以 HTTP 转发给程序，登录接口仍会被拒绝。程序不信任可伪造的转发头。后续如果接入反向代理，需要独立验证代理身份和转发边界，不能简单放行头部。

临时登录在本容器生命周期内可供自动归档使用；退出账号或停止容器才清除。重启后若无保存凭据，自动归档暂停，需登录后重新开启。勾选保存后可跨重启使用，但厂商会话失效仍需手动重新登录。升级和重建容器时同时保留原凭据目录与独立密钥目录；丢失密钥无法解开原文件，可退出账号后重新登录，不要用新密钥覆盖旧密文。已明确被 MQTT 拒绝的凭据停止自动重试；普通网络故障保留原重试策略。

退出账号会停止当前任务、关闭计划并删除程序保存的文件；不会删除只读外部会话及备份，不会撤销厂商 token。程序以 `account-disabled` 标记禁止回退旧账号。切回外部会话模式时，停止服务、确认外部文件有效，再删除此无凭据标记后启动。

## Mac 容器开发验证（不是电脑版入口）

电脑按需导出请使用 [电脑版入口](desktop.md)，无需 Docker。以下仅用于容器页面与隔离验证。

Docker Engine 可以由 Colima 提供。按 Colima 官方安装说明安装 Docker、Compose 和 Colima；启动后指定对应 Docker context。Mac 使用额外的 `deploy/compose.mac.yaml`，只把网页映射到本机 `127.0.0.1:8080`，不向局域网开放。

Mac 虚拟机与 Linux/NAS host 网络不同，端口映射可能改变回调来源地址。本覆盖文件只用于设置页与隔离验证，不能据此认定真实设备回传可用。不要为了使测试通过而关闭接收端的设备 IP 校验。

## 容器停止不一定是崩溃

旧单次入口设置 `PAWZZ_ONCE=1` 后，无论成功还是失败都会退出。现在默认入口改为常驻网页，导出子进程的退出码在网页显示。

| 单次进程退出码 | 含义 | 核对内容 |
|---|---|---|
| 0 | 本轮正常完成 | 新增数、原片和对应校验 sidecar；0 新增也可能是跳过近期录像或已存在文件 |
| 1 | 导出失败 | 页面故障类别；会话挂载、目录权限、网络和文件校验 |
| 4 | 厂商明确拒绝账号凭据 | 退出账号、重新短信登录；自动重试暂停 |
| 2 | 启动配置错误 | 必填值、IP、端口、周期、日期和源路径 |
| 130 / -15 | 收到停止请求 | 页面停止状态；必要时再核实设备维护通道清理 |
| 137 | 可能被强制结束 | Docker 的 OOMKilled、资源限制及人为 kill；不能仅凭 137 断言内存不足 |

低空间暂停使用退出码 `3`：输出文件系统不足 5 GB，或无法在接收本段后保留该余量。网页自动模式每 10 分钟检查并尝试恢复；单次命令行入口暂停后直接退出，释放空间后需重新运行。已有原片不会自动删除。

自动归档默认关闭，默认间隔 24 小时。开启后失败每 10 分钟重试，最多追加 3 次；仍失败则等待下个常规周期。目录或单段读取超时先在本轮追加重试最多 3 次，每次间隔 5 秒，期间不关闭维护通道；整轮结束或主动停止时尝试关闭。手动整轮失败不自动重跑。停止自动归档会同时取消重试和空间检查。

早期版本的缺失配置也可能产生退出码 1 和 traceback，以上区分适用于本版本。历史问题必须结合原容器版本与日志判断。

在群晖保留原容器，不先删除或重跑。只读取目标容器的以下字段，避免导出包含环境变量的完整 inspect：

```sh
docker inspect --format '{{json .State}}' pawzz-once
docker logs --tail 100 pawzz-once
```

替换为实际容器名。分享日志前隐去账号、序列号、IP、私有路径和 token。网页故障提示使用固定类别，不转发原始异常文本。管理进程最近 100 轮任务跨服务重启保存于配置目录 `history.json`；未正常结束的记录显示“结果未确认”。损坏的历史文件保留原文并阻止启动新任务，修复后重启服务。

| 故障类别 | 排查方向 |
|---|---|
| missing_file | 会话挂载、目录是否存在；文件挂载误建成目录 |
| permission_denied | 会话可读性、输出目录写入权限、DSM ACL |
| timeout | 设备在线状态、MQTT、回调地址/端口、防火墙 |
| io_or_network | 磁盘空间、端口冲突、DNS、TLS 证书 |
| invalid_data | 设置格式、会话 JSON、文件完整性 |
| operation_failed | MQTT 拒绝或维护回调异常 |

## 保留的单次入口

`deploy/compose.once.yaml` 保留旧部署方式，入口明确为 `python src/direct_exporter.py`。需要独立设置旧版环境变量：`PAWZZ_ALLOW_MAINTENANCE=yes`、`PAWZZ_DEVICE_IP`、`PAWZZ_CALLBACK_IP`、`PAWZZ_SN`、`PAWZZ_SESSION_FILE`（宿主机会话文件完整路径）、`PAWZZ_OUTPUT_DIR`（宿主机输出目录）。可选 `PAWZZ_CALLBACK_PORT`、`PAWZZ_START_DATE`、`PAWZZ_SOURCE`、`PAWZZ_INTERVAL`、`PAWZZ_REPAIR_VIDEO`（默认 `no`，设为 `yes` 另存无损修复版）；默认 `PAWZZ_ONCE=1` 与重启策略 `no`。不要与网页服务同时控制设备。配置放在仓库外的私有 env 文件，再通过 `docker compose --env-file 私有文件 -f deploy/compose.once.yaml up --build` 运行。

## 真实设备验收顺序

先导出指定已完成原片并核对三方 MD5、字节数与 sidecar；再次运行确认跳过且无覆盖。随后清空源路径验证目录发现与日期过滤，再验证停止/网络失败清理、磁盘权限和资源占用。以上通过才开启周期运行。

单元测试、本机 HTTP 测试和 Mac 镜像运行均不能替代群晖实机、不同固件、账号会话续期或真实网络中断验收。
